# GLM 5.3 Z AI Web Agent Prompt

Act as a senior creative technologist, product designer, and production frontend engineer. Build a complete promotional product website for **MCPveil**, a deterministic security testing CLI and test suite for Model Context Protocol (MCP) servers.

## Research first

Before making design or implementation decisions, inspect and understand the source repository and use it as the factual source of truth:

- GitHub repository: https://github.com/Pratham2511/mcpveli
- npm package: https://www.npmjs.com/package/mcpveil-cli

Read the README, package metadata, source structure, tests, documentation, and available project assets. Derive the website’s copy, feature descriptions, commands, installation instructions, and limitations from the repository. Never invent metrics, users, testimonials, enterprise customers, certifications, integrations, or guarantees.

## Design challenge

Create an original, high-quality product page that does not look like AI-generated website output. Do not use a standard SaaS template or a preselected cybersecurity look. Do not follow a fixed visual recipe. Discover a bold visual concept yourself; it can be surprising, experimental, editorial, cinematic, playful, architectural, or otherwise unconventional if it remains clear and credible.

Push the creative direction as far as you can while keeping the product easy to understand. Avoid generic gradient heroes, interchangeable glassmorphism cards, excessive rounded containers, fake dashboards, stock imagery, emoji icons, filler sections, and meaningless animations. Every visual decision should support the product narrative.

Design and implement an original MCPveil logo or brand mark. Make it a proper reusable asset using SVG, CSS, or another maintainable technique. Do not use an emoji or a generic copied shield logo.

## Implementation requirements

- Use Three.js for a meaningful interactive 3D or spatial element connected to the product story. It must not be a random background effect.
- Use the project’s current framework and installed dependencies when possible. Do not replace working project architecture unnecessarily.
- Build the complete responsive page for desktop, tablet, and mobile.
- Use real copy based on repository research and link to the actual GitHub and npm pages.
- Include an immediately understandable hero, product value proposition, how it works, a repository-derived quick-start/install flow, and a strong final call to action. Add other sections only when the source material supports them.
- Make GitHub and npm actions visibly useful and functional.
- Use semantic HTML and accessible controls. Support keyboard navigation, readable contrast, screen-reader labels, and prefers-reduced-motion.
- Provide a polished fallback when WebGL is unavailable or motion is reduced.
- Keep Three.js efficient: limit scene complexity, avoid unnecessary effects, dispose of resources, and prevent animation loops from continuing after unmount.
- Do not create fake buttons, fake data, fake testimonials, or unsupported security claims.

## Working method

1. Inspect the repository and summarize the real product facts you found.
2. Establish an original visual concept and explain why it fits MCPveil without copying an existing site.
3. Plan the page structure and interaction model.
4. Implement the full website with production-quality code, not a wireframe or partial prototype.
5. Test the build, navigation, responsive behavior, main interactions, external links, and Three.js fallback before finishing.

The finished result should feel like a carefully art-directed launch page for a serious open-source developer security tool—not a generic AI landing page. Prioritize originality, clarity, performance, accessibility, and factual accuracy.
